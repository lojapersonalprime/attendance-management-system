# Política de Segurança

## Reportar uma vulnerabilidade

Não abra issue pública para vulnerabilidades, credenciais expostas ou possíveis vazamentos de dados. Use o canal privado de segurança do GitHub do repositório, quando estiver disponível, e inclua somente a informação mínima necessária para reproduzir o problema sem dados pessoais.

Se um segredo for exposto, revogue-o imediatamente no provedor correspondente antes de reportar. Não envie chaves, senhas, URIs completas de banco, arquivos TXT reais ou dados de funcionários no relatório.

## Versões suportadas

Enquanto o projeto estiver na linha `0.x`, somente a versão estável mais recente receberá correções de segurança quando possível.

## Escopo

Relate falhas de autenticação, autorização, isolamento de Storage, exposição de configuração, tratamento de arquivos e acesso indevido a dados. Relatórios responsáveis receberão confirmação após análise pelos mantenedores.
